# 운영 절차

## 프로세스

| 프로세스 | 명령 | 역할 |
|---|---|---|
| API | `npm start` | 화면 제공, API, 웹훅 수신(원본 저장 후 즉시 200) |
| 워커 | `npm run start:worker` | 이벤트 정규화, AI 분석, 1분 주기 점검(답변 지연·견적 후속 할 일, 연동 장애/AI 한도 알림, 정기 보고), 일 1회 보관 정리 |

워커가 멈춰도 웹훅 원본은 `webhook_events`에 계속 저장되며, 워커 재시작 시 처리됩니다(10분 이상 `running`으로 남은 작업은 자동 복구).

## 백업 / 복원 (PostgreSQL)

모든 업무 데이터는 PostgreSQL 한 곳에 있습니다(첨부파일 원본은 현재 저장하지 않음).

```bash
pg_dump --format=custom --no-owner "$DATABASE_URL" > stayscene-$(date +%F).dump
```

```bash
pg_restore --clean --if-exists --no-owner --dbname "$DATABASE_URL" stayscene-YYYY-MM-DD.dump
```

- 관리형 DB를 쓰면 플랫폼의 자동 백업·시점 복구(PITR)를 켜고, 월 1회 별도 DB로 복원 리허설을 하세요.
- 백업 파일에는 상담 원문이 포함됩니다. 접근 권한을 제한하고 보관 기간 정책과 함께 파기하세요.

## 계정 회수 / 세션 종료

- 설정 → 구성원·권한 → **계정 회수**: 멤버십 비활성화 + 모든 세션 즉시 종료 + 작성 잠금 해제. 다음 요청부터 401.
- **세션 종료**: 계정은 유지하고 모든 기기에서 로그아웃.
- 모든 변경은 감사 로그(설정 → 감사 로그, `audit_logs`)에 남습니다.

## 데이터 보관 / 삭제

- 설정 → 데이터 보관에서 보관 일수를 정하면, 마지막 활동이 기간을 넘긴 상담 단위로 원문·내부 메모·AI 요약/누락 질문·분석 근거 연결·작성 잠금이 함께 삭제됩니다(외래키 CASCADE). 원본 웹훅 이벤트도 같은 기간으로 삭제됩니다. 별도 검색 인덱스는 없습니다(DB 내 검색). 답장 초안·관련 할 일도 함께 삭제됩니다.
- **현재 한계**: AI 직원 대화 기록(`ai_messages`)과 저장된 보고서(`reports`) 본문은 보관 정리 대상에 아직 포함되지 않습니다. 이 텍스트에 고객 요약이 들어갈 수 있으므로, 보관 정책 확정 시 함께 삭제하도록 확장이 필요합니다.
- 고객 식별정보 보관·파기 조건은 공급사·동의 조건 확인 후 확정하세요(docs/INTEGRATION.md 8번).
- 샘플 데이터는 설정 → 데이터 보관 → 샘플 데이터 삭제로 일괄 삭제합니다.

## 비밀값

- 서버 환경변수로만 관리: `SESSION_SECRET`, `ANTHROPIC_API_KEY`, 공급사 자격정보.
- 클라이언트 번들에 포함되지 않으며(프런트엔드는 `/api`만 호출), 서버 로그에서 쿠키·Authorization 헤더는 마스킹, 거부된 웹훅 본문은 로그에 남기지 않습니다.
- 알림 제목에는 상담 원문을 넣지 않습니다.

## 장애 대응

| 증상 | 확인 | 조치 |
|---|---|---|
| 새 상담이 안 보임 | 설정 → 연동 상태 → 원본 이벤트 수신함 | 실패 이벤트 재처리, 워커 실행 여부 확인 |
| AI '분석 대기' | 설정 → AI 비용 | 키 설정/한도 상향. 대기 상담은 '다시 분석'으로 재요청 |
| 401 웹훅 거부 | API 로그 `webhook rejected` | 공급사 서명 비밀값 확인 |
