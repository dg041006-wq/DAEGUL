# 업무 시트 → 앱 항목 대응표

기준 파일: 대표님이 제공한 `stay_scene.xlsx` (2026-11-15 내려받은 사본). **구글시트 실시간 연동이 아닙니다.** 원본 파일은 수정하지 않았고, 개인정보(이름·연락처·주소)는 이 문서와 저장소에 포함하지 않았습니다.

## 1. 시트 구조 파악 결과

| 항목 | 내용 |
|---|---|
| 탭 | 1개 (`시트1`), 사용 범위 1~369행, A~O열 |
| 수식 | **없음** (합계·집계 수식 없음 — 매출·정산은 시트에서 계산되지 않음) |
| 드롭다운 | E열 `브랜딩/촬영/기타`, I열 `패키지/베이직/스탠다드/프리미엄`, L열 `미진행/입금완료/진행 상태/진행중/완료` |
| 형태 | 달력형 예약 장부. 1행 머리글, 2~8행 '미지정 예약'(날짜 없는 예약), 9행 '예약' 이후 날짜별 행(2026-02-15 ~ 2027-01-01) |
| 실제 입력 | 예약/작업으로 볼 수 있는 행 109개, 고객(이름·연락처 기준) 약 70명, 날짜 범위 2026-02-15 ~ 2026-11-26 |
| 개인 일정 | C·D열 머리글이 직원 이름 → 각자의 휴가·출장·개인 일정 칸 (14건) |
| 메모 행 | 고객 없이 장소/할 일만 적힌 행(자재 발주, 시공 작업, 미팅 등) 33건 |

### 대표님이 시트를 쓰는 방식 (관찰)
- 하루 한 줄(같은 날 여러 건이면 날짜 칸을 비우고 아래 줄에 이어 씀)로 **촬영·브랜딩·스타일링·시공 일정과 고객**을 함께 관리.
- **단가(J)** 를 적고, **진행 상태(L)** 에 '입금완료'와 '완료'를 같은 칸에 섞어 기록 → 작업 완료와 입금 여부가 한 칸에 겹침.
- 계약금·선금(예: '먼저 받음'), 외주비(예: '○○형 100000', '140000>○○'), 현금영수증은 **특이사항이나 제목 없는 M~O열 메모**로 기록.
- 2026년 9월 이후에는 **연락처 칸(H)에 촬영 시간**을 적는 방식으로 바뀜 (예: 13:30, '오후 15:30', '14출', '기입예정').
- 매출 합계·미수금·월별 정산은 시트에서 따로 계산하지 않음.

## 2. 항목 대응표

| 시트 열 | 시트 항목 | 앱 항목 | 변환 규칙 |
|---|---|---|---|
| A | 날짜 | 작업 `scheduled_date` / 일정 `date` | 날짜 셀만 날짜로 인정. 날짜 칸이 빈 행은 바로 위 날짜를 이어받되 **'날짜 상속(확인 필요)'** 표시. '미지정 예약' 구역은 날짜 없음(`날짜 미정`) |
| B | 요일 | (검증용) | 실제 날짜의 요일과 다르면 **'요일 불일치'** 표시 (예: 2월 중순 일부 행) |
| C, D | 직원별 칸 | 팀 일정 `schedule_blocks` (개인, 대표만 열람) | 머리글 이름을 사람으로, 값을 일정 내용으로 |
| E | 구분 (촬영/브랜딩/기타) | 작업 `work_type` | 그대로. 비어 있으면 **'구분 없음'** 표시 (시공·스타일링을 추정해 채우지 않음) |
| F | 주소 | 작업 `address` + 제목 | 제목 = `예약자명 · 주소`. 고객 없이 주소/할 일만 있는 행은 일정 메모 |
| G | 예약자명 | 고객 `contacts.display_name` | 같은 전화번호 → 같은 고객, 전화번호가 없으면 같은 이름 → 같은 고객 |
| H | 연락처 | 고객 `phone`/`email` 또는 작업 `start_time`/`time_raw` | 010-0000-0000 형식 → 전화번호, 이메일 형식 → 이메일, 시간 셀·'13:30' → 시작 시간(**'연락처 칸 시간'** 표시), '14출'·'기입예정' 등 → 원문만 보존(**'시간 확정 불가'**), 숫자·날짜로 변한 값 → **'의미 불명'**, '010-5' → **'불완전 번호'** |
| I | 패키지 | 작업 `package` | 그대로 |
| J | 단가 | 작업 `listed_price` (시트 단가) | **확정 계약 금액으로 쓰지 않음.** 0원은 '0원 확인', 음수는 금액 반영 안 함 + '음수 금액' 표시 |
| K | 특이사항 | 작업 `notes` | 원문 보존. 시간 셀이면 시작 시간 후보. '먼저 받음'·'계약금' → **'입금 메모 있음'**, '○○형 금액' → **'비용 메모 있음'**, '현금영수증' → 증빙 메모 |
| L | 진행 상태 | 작업 `status` / 입금 기록 | '완료' → 작업 완료(입금 여부는 **알 수 없음** 표시) · '진행중' → 진행중 · '입금완료' → **'확인 필요 입금'**(금액·일자 없음, 합계 미포함) · '미진행' → 보류 · 빈 칸(지난 날짜) → **'상태 없음'** 표시 |
| M~O | (제목 없음) | 작업 `notes`에 `[M열] …` 형식으로 보존 | 의미를 추정하지 않음. **'제목 없는 열'** 표시 |

같은 날짜·장소·고객·단가가 파일 안에서 반복되면 **'파일 내 중복'** 으로 보류(가져오지 않음, 미리보기에서 선택). 같은 고객·장소의 다른 날짜는 **'재방문/연속 작업 후보'** 로만 표시합니다.

## 3. 가져오기 방법

1. 설정 → 시트 가져오기 → 파일 선택 (`.xlsx`)
2. 미리보기에서 확인 필요 행을 검토하고 행마다 `가져오기 / 제외 / 보류` 선택
3. '확인한 내용으로 반영' → 고객·작업·팀 일정·확인 필요 입금 생성
4. 같은 파일(또는 이후 버전)을 다시 올려도 **이미 가져온 행은 다시 만들지 않습니다** (원본 행 내용 기반 키)
5. 반영 후 작업 화면에서 확인 필요 항목을 수정하면 표시가 줄어듭니다.

로컬 검증 결과(이 파일): 작업 109건, 고객 70명, 팀 일정/메모 47건, 확인 필요 입금 7건 생성 / 같은 파일 재반영 시 신규 0건.

## 4. 시트 방식의 불편한 점과 앱에서의 개선

| 시트의 불편함 | 앱에서 |
|---|---|
| 작업 완료와 입금 여부가 한 칸 | 작업 상태와 입금 기록을 분리. 입금은 '확인 입금'(금액·일자·근거)과 '확인 필요'로 구분 |
| 계약금·잔금·외주비가 메모에 흩어짐 | 작업마다 입금(계약금/잔금/전액/환불), 비용(외주·자재·기타, 지급처) 기록 → 미수금·공헌이익 자동 계산 |
| 연락처 칸을 시간으로 사용 | 연락처와 시작 시간 칸을 분리 |
| 같은 날 여러 건이면 날짜를 비워 둠 | 작업마다 날짜가 있음. 일정 화면에서 날짜별로 묶어 보기 |
| 고객 이력을 보려면 시트 검색 | 고객 화면에 문의·견적·계약·작업·입금 이력 시간순 정리 |
| 촬영 전 준비(주소·주차·시간 확인)가 메모 | 작업마다 사전·사후 체크리스트, 내일 작업에 주소·시간·연락처가 없으면 운영비서가 보고 |
| 월 매출·미수금 계산 없음 | 정산 화면: 월별 확인 입금, 단가 합계와 확정 금액 합계 분리, 미수금 확인 대상 |

입력 위치는 한 곳입니다: 고객·작업은 작업 화면/고객 화면에서 한 번 입력하면 일정·정산·보고·AI 직원 답변에 같은 데이터가 쓰입니다.

## 5. 구글시트 읽기 전용 연동 (준비 완료, 미연결)

- 구조: 서비스 계정으로 시트를 **읽기만**(scope `spreadsheets.readonly`) → xlsx와 같은 해석기로 **미리보기 생성** → 대표가 확인 후 반영. 원본 시트에 쓰지 않습니다.
- 필요한 설정 (대표님 작업):
  1. Google Cloud 콘솔에서 프로젝트 생성 → Google Sheets API 사용 설정
  2. 서비스 계정 생성 → JSON 키 발급
  3. 배포 환경 비밀 변수 `GOOGLE_SERVICE_ACCOUNT_JSON`에 JSON 전체를 넣기 (채팅에 붙여넣지 마세요)
  4. 업무 시트를 서비스 계정 이메일(`…@….iam.gserviceaccount.com`)에 **뷰어**로 공유
  5. 앱 설정 → 시트 가져오기 → 스프레드시트 ID 저장 → '원본 시트 읽어서 미리보기 만들기'
- 연결 테스트가 성공하기 전에는 상태가 '연결 확인됨'으로 바뀌지 않습니다. 현재 상태: **미연결** (서비스 계정 없음).
