## 2. 실제 동작 (로컬·테스트로 확인)

| 기능 | 확인 방법 |
|---|---|
| 업무 시트 가져오기 (미리보기→확정, 플래그, 재가져오기 중복 없음) | 실제 파일로 로컬 실행: 작업 109·고객 70·일정 47·확인 필요 입금 7, 재반영 0건 / 합성 시트 자동 테스트 |
| 작업·일정·체크리스트·납품·정산(확인 입금 vs 확인 필요, 미수금) | 자동 테스트 + 화면 확인 |
| 고객별 이력, 통합 검색, 첨부(10MB, 권한 검사) | 자동 테스트 + 화면 확인 |
| 즉시 보고: 신규 문의·계약 확정·입금 확인·일정 변경·취소·불만 신호·납기 위험·준비 누락·답변 대기·작업 실패 | 자동 테스트(중복 방지 포함) |
| 대표 전용 보고방(담당별), 보고 버튼(할 일 등록·내일 다시 알림·답장 초안·담당 지정·처리 완료) | 자동 테스트 + 화면 확인 |
| 대화 명령 실제 실행 (권한 검사, 실행 결과는 서버 기록으로 표시) | 규칙 모드에서 '할 일 넣어줘'·'미수금'·'일정' 실행 확인. 모델 모드의 도구 실행은 코드만 있음(실제 키로 미검증) |
| 일일(19:00)·주간(금 19:10) 보고, 놓친 회차 보충, 회차당 1건, 테스트 실행 분리 | 자동 테스트(고정 시각 주입) + 로컬 워커 실행 |
| 웹 푸시 (VAPID, 구독·만료 처리) | 로컬 HTTPS 가짜 푸시 엔드포인트로 전송/410 만료 테스트. **실제 브라우저 푸시 서비스(FCM/APNs)는 미확인** |
| PC↔휴대폰 실시간 동기화(SSE), 연결 끊김 표시·재연결 시 재동기화, 저장 중/완료/실패, 오래된 화면 덮어쓰기 방지(409) | DB 변경 알림 자동 테스트 + 409 테스트. 두 실기기 간 확인은 미실시 |
| 고객 발송 큐 (승인·중복 방지·확인 불가 시 자동 재전송 금지) | 테스트 공급사로 자동 테스트. **실제 카카오 발송 없음** |
| 경영 제안 (근거·기대효과·첫 행동, 반복 금지, 채택→할 일) | 실제 시트 데이터로 3건 생성 확인 + 자동 테스트 |
| AI 오류 구분(인증·잔액·권한·한도·정책 거절), 거절 시 다른 모델 자동 전환 제거, 호출 상한 | **로컬 가짜 API 서버** 테스트 (실제 Claude 아님) |
| 권한: 직원별 조회·수정·발송·AI 도구 | 자동 테스트 |
| 데이터 삭제: 고객 삭제·보관 기간 정리가 AI 대화·보고서·사건·알림·첨부까지 반영 | 자동 테스트 |

## 4. 남은 일 (우선순위)

1. 운영 배포(차단) → 실기기 설치·푸시 확인
2. 실제 키로 AI 직원 도구 실행·상담 분석·답장 초안·보고서 해석 검증, 프롬프트 조정
3. 카카오 상담톡 공급사 결정 → 어댑터 구현·테스트 채널 검증 (그 전까지 수동 등록·가져오기·테스트 수신 사용)
4. 견적서 문서 생성, 캘린더 월간 보기, 작업 시간 기록(시간 대비 수익 분석용)
5. 로그인 시도 제한을 DB 기반으로(다중 인스턴스 대비)
