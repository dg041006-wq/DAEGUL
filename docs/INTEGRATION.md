# 카카오 상담 연동 — 0단계 검증 계획

> 상태: **미연동 (검증 전)**. 이 저장소에는 실제 카카오/채널톡/딜러사 연동 코드가 없습니다.
> 화면과 데이터는 `demo` 공급사(샘플)로만 동작하며 '샘플 데이터 / 카카오 미연동'으로 표시됩니다.
> 요구사항 문서의 2026-11-15 확인 내용을 기준으로 작성했으며, 실제 진행 시점에 공식 문서와 계약 조건을 다시 확인해야 합니다.

## 1. 전제 (요구사항 2절)

- 일반 카카오디벨로퍼스 채널 API(채널 추가, 채팅방 진입, 관계 조회)는 **채널 1:1 대화 전체 조회/수신 API가 아님**.
- 채널 상담 수발신 시스템 연동은 **상담톡(공식 딜러사) 경로**로 검토.
- 상담톡 전환 시 **기존 카카오 채널 관리자 웹/앱의 채팅 메뉴 사용이 중지**됨.
- 기존 채널 관리자 대화 이력이 신규 시스템으로 **자동 이전된다고 가정하지 않음**.
- 관리자센터 스크래핑, 비공식 개인 카카오 계정 조작은 사용하지 않음.

## 2. 경로 비교

| | A. 상담 솔루션(예: 채널톡) + 상담톡 | B. 상담톡 딜러사 API 직접 |
|---|---|---|
| 우리 앱 연결 | 솔루션의 공식 OpenAPI/웹훅 | 딜러사 API |
| 상담원 답장 화면 | 초기엔 솔루션 화면 사용 가능 | 우리 앱 구현 필요 |
| 확인 필요 | 카카오 유입 메시지가 웹훅/조회 API에 포함되는지, 상담원 답변 포함 여부, 요금제별 API 제공 범위 | 계약 조건, 메시지 규격, 발송 제약 |
| 주의 | 2026 OpenAPI 신버전 전환 공지 — 과거 `/v5` 예제 사용 금지. 현재 명세(https://api-doc.channel.io/)로만 구현 | 딜러사별 상이 |

**추천: A부터 검증.** 이유 — (1) 상담원 답장 화면을 공급사 것으로 바로 쓸 수 있어 우리 앱은 수신·분석·보고에 집중 가능, (2) 앱의 공급사 어댑터 구조상 A→B 교체 시 `integrations/<provider>.ts` 하나만 추가하면 수신함·중복 방지·보고·발송 큐가 그대로 동작, (3) 계약 전 무료/체험 계정으로 웹훅 수신 범위를 먼저 확인할 수 있는 경우가 많음(요금제별 확인 필요).
A가 카카오 메시지 웹훅·상담원 답변·조회 API 중 하나라도 제공하지 않으면 B 검토. 둘 다 미확정이면 앱은 계속 '미연동'으로 표시.

**현재 연동 상태 확인 결과 (2026-11-16):** 저장소·배포 설정·환경변수에 어떤 상담 공급사 자격정보도 없음 → 검증할 기존 연결 없음.

**그동안 쓰는 방법:** 상담함 '+ 상담 등록'(수동 등록: 전화·인스타·카카오 내용 옮겨 적기), 과거 기록 JSON 가져오기, 업무 시트 가져오기. 공급사 연동 전 흐름 시험은 '테스트 수신'(체크 시 `test` 출처로 분리, 집계·운영 보고 제외) 또는 `POST /api/webhooks/test/<orgId>` (`TEST_WEBHOOK_SECRET` HMAC 서명).

## 4. 최초 기술 검증 절차 (테스트 채널 / 허용된 테스트 환경)

1. 공급사 테스트 계정 발급 → 서버 환경변수에 자격정보 등록(아래 5절). **채팅에 키를 붙여넣지 말 것.**
2. 공급사 현재 명세로 `src/server/integrations/<provider>.ts` 어댑터 구현:
   - `verify()` — 공급사 공식 서명/토큰 검증
   - `eventId()` — 공급사 이벤트 ID (없으면 메시지 ID 기반)
   - `normalize()` — `NormalizedEvent`로 변환 (발신자 유형: customer / staff / bot / system)
   - `backfill()` — 공급사가 누락 조회를 지원할 때만
3. `registry.ts`에 등록, `integrations` 행을 `testing` 상태로 설정.
4. 공급사 웹훅 URL을 `https://<앱 주소>/api/webhooks/<provider>/<orgId>`로 설정.
5. 테스트 고객 계정으로 메시지 발송 → 상담원 답변 → 상담 종료/재개.
6. 확인 항목(요구사항 필수 시나리오 6):
   - [ ] 수신 시각 / 발신자 / 본문이 공급사 원본과 일치
   - [ ] 상담원 답변이 `staff`로 기록됨, 자동 안내는 `bot`
   - [ ] 같은 이벤트 재전송 시 중복 없음 (자동 테스트로 데모 공급사 기준 검증됨)
   - [ ] 순서 역전 도착 시 화면 재구성 정상
   - [ ] 서버 일시 중단 후 공급사 재시도/백필로 복구, 누락 건수 = 0 (공급사 원본과 대조)
7. 앱 내 답장은 공급사가 지원하고 실제 발송 검증이 끝난 뒤 별도로 활성화 (현재 `sendEnabled: false` 고정).
8. 실채널 전환·유료 계약은 비용·전환 영향(채팅 메뉴 중지, 이력 이전 불가 가능성)을 대표에게 제시한 후 진행.
9. 검증 완료 시에만 `integrations.status = 'verified'` 로 변경 → 화면의 '미연동' 표시가 해제됨.

## 5. 자격정보 설정 위치

- 로컬: `.env` (git에 커밋되지 않음, `.env.example` 참고)
- 운영: 배포 플랫폼의 비밀(Secret) 환경변수
- 변수명은 공급사 명세 확정 후 정합니다. `.env.example`의 `CHANNELTALK_*`는 자리표시이며 아직 코드에서 읽지 않습니다.

## 6. 현재 코드의 연동 관련 구현 범위

- 구현됨: 원본 이벤트 수신함(`webhook_events`), 서명 검증 실패 시 거부, (공급사·이벤트 ID) 중복 제거, (공급사·메시지 ID) 중복 제거, 순서 역전 안전 갱신, 실패 시 재시도 큐 + 관리자 재처리, 연동 상태/오류 화면 노출, 샘플 데이터 일괄 삭제.
- 구현됨(추가): 고객 발송 큐(승인·멱등 키·확인 불가 상태·상태 확인 절차), 공급사 `send`/`getSendStatus` 인터페이스, 테스트 공급사.
- 미구현: 실제 공급사 어댑터, 백필, 실제 발송, 공급사 첨부파일 다운로드.
